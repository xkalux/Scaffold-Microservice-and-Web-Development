# API contracts

**Owner:** Microservices

**Status:** No product/authentication API contract is accepted yet. The starter health route is not a full ecommerce contract.

Web uses an explicit Web-owned mock/fixture until the required contract is accepted. Record its assumed fields, success/error cases and contract version beside the fixture. Do not depend on which course meets first in the same week: use a previously accepted deliverable or a local mock for the current contract.

Before accepting a contract, specify method/path, input/output schemas, status codes, error shape, authentication and authorization, version, and representative fixtures. Record acceptance and consumer feedback. Microservices owns contract edits; Web records consumer notes in [Web docs](../web/README.md) and requests changes through [Change Requests](../change-requests/index.md).

A contract change must identify affected consumers, fixtures, tests and migration/compatibility needs. Deliveries and handoffs are written in English.
